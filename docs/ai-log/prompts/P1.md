# Initial project setup — CarRentalApp (SDU Mobile Software Design & Development, Fall 2026)

You are setting up the foundations of a group university project. Six students will work on this repo,
mostly with AI assistants, so everything you create must make the course rules easy to follow
automatically. Do NOT implement app features yet. This task is infrastructure and conventions only.

## Context
- App: simple car rental app in React Native. Users view a list of cars, view car details, place a booking.
  It starts with embedded dummy data. Later it fetches from an API and persists data locally.
- Stack already scaffolded: Expo SDK 57 + TypeScript, React Navigation (native-stack), React Context API.
  Expo SDK 57 is newer than your training data. Read https://docs.expo.dev/versions/v57.0.0/ before
  choosing packages or config. Install Expo-related packages with `npx expo install` so versions stay compatible.
- Mandatory course NFRs (these will shape the architecture later, so design folders for them):
  - K1 offline availability of already-fetched data
  - K2 failed writes queued and retried with backoff
  - K3 sync status (pending / failed / completed) always visible to the user
- Deadline: October 2. Keep everything lightweight. Skip anything that doesn't pay off in 10 days.

## Course AI policy (must be encoded in the repo)
1. All AI use must be disclosed. Every significant interaction is logged (ID, date, tool & mode, task,
   prompt or link, verification, decision: kept/modified/discarded). There is also a failure log with at
   least 3 entries per project, documenting AI output that was wrong or off-spec and how it was caught.
   Per use case the course also asks for: evaluation of how well the AI did, and alternatives the team
   looked up themselves without AI.
2. AI-generated code enters `main` only through a pull request that includes tests, is reviewed by a teammate
   who did NOT generate it, and passes CI. "The model wrote it and it ran" is not verification.
3. The repo keeps an agent rules file (AGENTS.md / CLAUDE.md) with conventions, architecture and definition
   of done, and it evolves as we learn what agents get wrong. Its git history is graded evidence.
4. Any team member may be asked to explain or live-modify any line. Code must stay simple and readable.
