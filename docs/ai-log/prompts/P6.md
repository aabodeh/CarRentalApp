## 1. Repository layer
`src/repositories/carRepository.ts` — the seam. Today it returns dummy data; later the same interface
is backed by the API + local cache, with no screen changed.

- Interface: `getCars(): Promise<Car[]>`, `getCarById(id: string): Promise<Car>`.
- Async even though the data is local, with a small artificial delay (~400ms, from a constant marked
  as temporary). Real loading states now means no rewrite when the API arrives.
- `getCarById` throws a typed `CarNotFoundError` — screens must handle a missing car.
- No React, no navigation imports. Plain unit tests in `__tests__/repositories/`.

## 2. Hook
`src/hooks/useCars.ts` (+ `useCar(id)`), returning a discriminated union, not loose booleans:
`{ status: 'loading' } | { status: 'error'; error; retry } | { status: 'empty' } | { status: 'ready'; cars }`.
That way the screen cannot render a state we forgot to design. Cancel/ignore the result if the hook
unmounts first. Test with `@testing-library/react-native`'s `renderHook`.

## 3. Components
`src/components/`, all consuming theme tokens only, no hard-coded values:
- `CarCard` — expo-image photo (with a placeholder colour while loading), make + model as display type,
  year/seats/transmission/fuel as small tracked uppercase metadata, price per day as the strongest
  non-title element. Unavailable cars are visibly de-emphasised and not pressable, and say why.
- `Screen` — safe-area wrapper with our background.
- `StateView` — shared empty / error / loading presentation, so every screen states the same way.
- `Skeleton` — shimmering placeholder card for loading (respect reduce-motion: static when on).

## 4. CarListScreen
- `FlatList` of `CarCard`, generous spacing, editorial rhythm. Header with a short title and the car
  count. `keyExtractor` by id, `contentContainerStyle` for padding, no inline styles.
- All four states wired: loading (3 skeletons), error (with a working retry), empty, ready.
- Pull-to-refresh via `RefreshControl`, tinted with the accent.
- Tap a car → navigate to `CarDetails` with `{ carId }`. Update `RootStackParamList` accordingly
  (this replaces the `undefined` params) and type the screen props properly.

## 5. Motion (this is graded, make it feel deliberate)
Reanimated, all of it gated on `useReducedMotion`:
- Cards fade + translate up on mount, staggered by index (cap the stagger so item 20 isn't late).
- Press: scale to ~0.97 with a spring, plus `expo-haptics` light impact on press-in.
- Skeleton shimmer loops while loading.
- Keep durations and easings in `src/theme/motion.ts` — no magic numbers in components.
Rule: motion supports comprehension (where did this come from, what did I just press). If an animation
only shows off, drop it.

## 6. Accessibility (must hold, we audit this)
Every pressable: `accessibilityRole="button"`, a label that reads as a sentence
("Toyota Corolla 2021, 450 kroner per day"), and a ≥44pt touch target. Decorative images
`accessible={false}`. Text must not clip at 200% size: no fixed heights on text containers,
card layouts reflow. Add a test asserting each card exposes an accessibility label.

## 7. Tests
Repository, hook and screen. Screen tests query like a user (`getByText`, `getByRole`) and cover:
renders the list, shows skeletons while loading, shows the error view and recovers on retry, shows the
empty view, navigates with the right carId on press, does not navigate for an unavailable car.
Name the tests after acceptance criteria, Gherkin-style, per AGENTS.md.
