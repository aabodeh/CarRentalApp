# PR 1 — domain types, design system and dummy data

Branch `feat/domain-and-design-system` from main. Read AGENTS.md first. No screens in this PR —
this is the foundation the UI will be built on. Start in plan mode and wait for my OK.

## Context
Car rental app, React Native + Expo SDK 57 (read https://docs.expo.dev/versions/v57.0.0/ before
picking APIs). The app must look genuinely good, not like a bootstrapped template: this is graded on
design quality and we get credit for animation and polish. It must also pass a measured accessibility
audit (WCAG AA contrast, 44pt touch targets, works at 200% text size).

## 1. Design direction
We are NOT building another blue corporate rental app. Direction to implement:

- **Editorial / product-catalogue feel.** Cars are presented like objects in a design magazine:
  large images, generous whitespace, confident typography, minimal chrome.
- **Palette:** near-black ink (#12120F) on a warm off-white paper (#FAF8F4), with a single saturated
  accent used sparingly for actions and status. Pick the accent yourself from the "signal orange /
  amber" family, and verify it passes AA contrast on both the paper and ink backgrounds — if it
  doesn't, darken it until it does and say what you picked and why.
- **Typography:** one sans family, loaded via `expo-font` / `@expo-google-fonts`. Pick something with
  character but readable (e.g. a grotesque). A large display size for car names, a small uppercase
  tracked style for metadata labels. Ship a type scale, not ad-hoc font sizes.
- **Shape language:** pick one radius scale and one elevation approach and apply them consistently.
  Prefer subtle borders over heavy shadows.
- Dark mode: define the tokens for it now (`useColorScheme`), even if we only ship light first.

Put all of this in `src/theme/` as tokens: `colors`, `spacing` (4pt scale), `radii`, `typography`,
`durations`/`easings` for motion. Nothing in the app hard-codes a hex, a size or a duration.
Add `src/theme/README.md` explaining the direction in ~10 lines, so the rest of the team (and the
Surface plane of the design doc) can follow it.

## 2. Animation and image foundation
Install and configure, with `npx expo install`:
- `react-native-reanimated` (babel plugin configured, verify the app still starts)
- `expo-image` (better caching than Image — matters for K1 offline later)
- `expo-haptics` (light feedback on primary actions)
- fonts via `expo-font` + the `@expo-google-fonts` package for the family you chose

Add `src/theme/motion.ts` with our motion rules: durations (fast/base/slow), easing curves, and a
note that motion must respect `AccessibilityInfo.isReduceMotionEnabled()`. Add a `useReducedMotion`
hook in `src/hooks/` that animations will use. Document in AGENTS.md: every animation must degrade
to no animation when reduce-motion is on — that is an accessibility requirement, not an option.

## 3. Domain types
`src/types/` — these mirror the design doc's class diagram, so keep them minimal and justified:

```ts
type Car = {
  id: string;
  make: string; model: string; year: number;
  imageUrl: string;
  pricePerDay: number;      // DKK
  seats: number;
  transmission: 'manual' | 'automatic';
  fuel: 'petrol' | 'diesel' | 'electric' | 'hybrid';
  location: string;
  available: boolean;
};

type Booking = {
  id: string;
  carId: string;
  startDate: string; endDate: string;   // ISO YYYY-MM-DD, not Date: survives JSON round-trips
  totalPrice: number;
  createdAt: string;
  syncStatus: 'pending' | 'failed' | 'completed';   // K3
};
```
If you think a field is missing or wrong, say so in the plan instead of silently changing it —
these have to match what goes in the design doc.

## 4. Dummy data
`src/data/dummy/cars.ts` — 10 cars, typed, realistic for a Danish rental app in Odense/Funen:
a believable mix (small city cars, EVs, a station wagon, a van), plausible DKK day rates, one or two
marked unavailable so empty/disabled states are exercisable. Images: remote URLs from a source that
allows hotlinking (Unsplash) — check each URL actually resolves; no broken images.
Note in the folder README that this is temporary and gets replaced by the API in a later PR.

## 5. Small utils + tests
- `src/utils/`: `formatPrice` (DKK, da-DK), `formatDateRange`, `daysBetween`, `calculateTotalPrice`.
  Pure functions, no React.
- Tests in `__tests__/utils/` for each, including edge cases (same-day range, invalid range).
- A test asserting every dummy car satisfies the `Car` shape and has a unique id.
- A test asserting the theme's accent passes AA contrast against both backgrounds (compute the
  contrast ratio in the test — this is evidence for the design doc's accessibility audit).
