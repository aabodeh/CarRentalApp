## 1. The API
No backend of our own — we don't have time to build and host one. Use MockAPI (mockapi.io) or
equivalent free hosted JSON API: I'll create the project and seed it with our 10 cars from
`src/data/dummy/cars.ts`. Give me the exact resource schema and the seed JSON to paste.
- `src/services/api/` — a thin typed client: base URL from `app.json` `extra` (not hardcoded in
  code), `fetch` with an `AbortController` timeout (~8s), typed errors that distinguish network
  failure / timeout / bad status / malformed payload.
- Runtime validation of the payload before it becomes a `Car`. Hand-written type guards, no new
  dependency. A server that returns a missing field must produce our typed error, not a crash later.
- Keep `src/data/dummy/` in the repo as the seed source and say so in its README.

## 2. Local cache (K1)
- `src/storage/` — AsyncStorage (`@react-native-async-storage/async-storage`, via `npx expo install`),
  keys namespaced and versioned (e.g. `carrental.v1.cars`), with a stored `fetchedAt` timestamp.
- `carRepository` becomes: return cached data immediately if present, then refresh from the API in the
  background and update; on API failure with a cache present, keep serving the cache and report
  staleness; on API failure with no cache, that is the error state.
- Screens must not change beyond consuming the new fields. If a screen needs rewriting, the seam was
  wrong — say so in the plan instead of working around it.
- Bookings persist too, so they survive an app restart. This is the storage the retry queue will use
  in PR 5, so design the shape with that in mind but do not build the queue here.

## 3. Offline surface
- `useNetworkStatus` hook over `expo-network` (`npx expo install`). React to changes, don't poll.
- A quiet, persistent offline banner (respecting reduce motion when it appears) that states what
  still works: browsing cached cars, yes; fresh availability, no.
- Show data age where it matters ("Updated 5 minutes ago"), and mark cached data as such on details.
- Booking while offline must not silently fail: the button stays enabled, the booking is created
  `pending`, and the copy says it will sync. PR 5 makes the retry real.
